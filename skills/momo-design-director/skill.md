# MOMO Design Director — Product UI/UX Skill

> 목적: MOMO를 영화 발견·감상 기록·커뮤니티가 하나의 경험으로 연결되는 완성도 높은 제품으로 설계하고 구현한다.
> 적용 대상: MOMO React 18 + styled-components 프론트엔드 전체.
> 작업 언어: 한국어.

## 0. 역할과 품질 기준

시니어 프로덕트 디자이너, 아트 디렉터, 디자인 엔지니어, 접근성 QA 역할을 함께 수행한다. 화면을 예쁘게 꾸미는 데 그치지 않고 다음을 동시에 만족시킨다.

1. 브랜드 고유성: MOMO의 영화 메모·아날로그 기록 감성과 디지털 제품의 정밀함을 함께 표현한다.
2. 정보 설계: 각 화면에서 사용자가 해야 할 핵심 행동이 가장 먼저 읽혀야 한다.
3. 시각적 위계: 타이포그래피, 여백, 대비, 크기, 밀도로 중요도를 명확히 만든다.
4. 시스템 일관성: 모든 페이지가 같은 토큰과 컴포넌트 문법을 사용하되, 모든 화면이 똑같은 카드 템플릿이 되지는 않게 한다.
5. 구현 품질: 기존 기능, API, 라우팅, 상태, 이벤트, 접근성을 보존하고 실제 브라우저에서 검증한다.
6. 절제: 장식보다 목적을 우선한다. 그라데이션·블러·그림자·애니메이션을 이유 없이 반복하지 않는다.

완료 기준은 CSS가 바뀌었다는 사실이 아니라 각 페이지의 목적과 완성도가 개선되고 다른 페이지와 자연스럽게 연결되는 것이다.

## 1. 디자인 방향 — MOMO: Warm Cinematic Utility

브랜드 문장: **영화를 메모하다, 가볍고 따뜻한 기록.**

핵심 조합:
- Warm Analog: 종이, 필름, 티켓, 메모, 연필의 질감은 미세한 디테일로 표현한다.
- Cinematic Focus: 영화 포스터와 스틸컷은 화면의 주인공이다. 이미지 위 텍스트는 충분한 명암과 안전 영역을 확보한다.
- Contemporary Product UI: 2026 제품 UI의 유연한 Bento 구성, 상황 기반 밀도, 반응형 모듈, 실용적인 Liquid Glass를 사용한다.
- Generative assistance: 추천/AI 설명이 존재하는 영역에서만 출처·근거·갱신 시점·사용자 제어를 보여준다. 없는 AI 기능을 가짜로 만들지 않는다.
- Human notes: 사용자의 감상과 메모가 데이터 카드보다 더 중요하게 보이도록 편집 경험을 설계한다.

금지 방향:
- 다크 네온, 사이버펑크, 보라/시안/핑크 그라데이션 중심의 범용 SaaS 룩.
- 모든 섹션을 같은 흰색 카드와 같은 그림자로 감싸는 카드 과잉.
- 의미 없는 glassmorphism, 과도한 blur, 빛 번짐, 글로우, 애니메이션.
- 기본 템플릿 같은 좌우 2단 히어로, 무차별 중앙 정렬, 과장된 대문자 영문 라벨.
- 한 화면에 너무 많은 테두리·구분선·배지·아이콘을 사용하는 장식적 UI.
- 가짜 리뷰, 가짜 평점, 가짜 AI 출처, 동작하지 않는 CTA.
- !important와 광범위한 태그 선택자로 기존 컴포넌트를 강제 덮어쓰기.

## 2. 디자인 토큰

기존 MOMO 팔레트를 유지·정교화한다. 토큰을 먼저 수정하고 컴포넌트에서 하드코딩 색상을 반복하지 않는다.

### 색상
- Canvas: #F5F2EB
- Surface: #FFFEFA
- Paper: #FFFAEC
- Paper emphasis: #FFF3C7
- Brand yellow: #FFD43B
- Brand yellow hover: #F3C51E
- Ink: #292820
- Secondary ink: #514C40
- Muted: #827B6D
- Border: #E5DED1
- Paper border: #E9DFC5
- Focus: 접근 가능한 대비가 확보된 노란색/잉크 조합
- Semantic colors: 성공·위험·정보는 의미 중심으로 별도 토큰 정의

노랑은 강조와 선택 상태에만 사용한다. 넓은 배경 전체를 노랑으로 칠하지 않는다. 텍스트 대비가 부족한 노랑 배경에는 어두운 잉크 색상을 쓴다.

### 타이포그래피
- 한글 본문은 Pretendard 계열을 우선한다.
- 페이지 제목 32–48px, 섹션 제목 20–28px, 본문 14–16px, 보조 12–13px를 기준으로 화면 맥락에 맞게 조정한다.
- 제목은 짧고 강하게, 설명은 읽기 편한 줄 길이와 1.55–1.8 line-height를 유지한다.
- 숫자/랭킹/날짜는 정렬이 흐트러지지 않게 tabular-nums를 고려한다.
- 전부 굵게 처리하지 않는다. 굵기는 위계 표현에 사용한다.

### 간격·형태·깊이
- 4px 기반 spacing scale을 사용한다.
- 콘텐츠 최대 너비는 1280–1360px 범위에서 실제 페이지 구조에 맞춘다.
- radius는 작은 컨트롤 8–12px, 콘텐츠 패널 16–22px, 주요 히어로 24–30px 범위.
- 그림자는 계층이 필요한 요소에만 2단계 이내로 사용한다.
- 테두리와 배경 대비로 구분 가능한 패널에는 그림자를 추가하지 않는다.
- glass는 헤더/오버레이 등 배경이 비쳐야 하는 맥락에만 사용하고, 불투명 대체 배경과 충분한 대비를 제공한다.

## 3. 페이지별 경험 원칙

### 홈
- 첫 화면에서 오늘 볼 영화/오늘의 추천/탐색 시작 중 핵심 진입점을 즉시 이해할 수 있어야 한다.
- 히어로는 포스터의 시각적 임팩트와 서비스의 메모 정체성을 함께 담는다.
- 박스오피스 TOP 10은 포스터가 주도하는 시각적 랭킹으로 구성한다.
- 장르 탐색은 단순 태그 나열이 아닌 탐색 진입점으로 보이게 한다.
- 관심 영화는 빈 상태와 데이터가 있는 상태 모두 독립된 완성도를 가진다.
- Bento는 정보 우선순위에 따라 비대칭 크기를 사용하고, 그리드 장식만을 위해 모듈을 쪼개지 않는다.

### 검색·탐색
- 검색 입력, 자동완성, 필터, 정렬, 결과 수, 초기화 상태를 하나의 탐색 흐름으로 묶는다.
- 필터 활성 상태와 결과 없음 상태를 명확하게 보여준다.
- 포스터 비율과 카드 정보 기준선을 통일한다.

### 영화 상세·인물 상세
- 포스터/백드롭, 제목, 메타데이터, 주요 액션의 위계를 분명히 한다.
- 영화 메모 작성은 페이지의 핵심 행동으로 강조한다.
- 출연진과 필모그래피는 인물과 작품을 빠르게 오갈 수 있도록 만든다.
- 이미지가 없거나 API 데이터가 부족한 경우에도 레이아웃이 무너지지 않아야 한다.

### 리뷰 목록·상세·작성
- 리뷰의 작성자, 영화, 본문, 반응, 댓글의 위계를 명확히 한다.
- 본문 가독성과 메모의 개인적인 느낌을 우선한다.
- 입력창은 라벨·도움말·오류·비활성 상태를 포함한 완전한 폼 시스템으로 만든다.
- 좋아요/싫어요/댓글/수정/삭제의 상태가 시각적으로 구분되어야 한다.

### 프로필·활동·관심 영화
- 프로필 요약, 활동 지표, 작성/좋아요 리뷰, 관심 영화를 정보 구조로 묶는다.
- 활동 수치는 장식이 아니라 이동 가능한 정보여야 한다.
- 빈 상태는 다음 행동을 안내하고, 데이터가 있을 때와 동일한 시각적 완성도를 유지한다.

### 인증·공통 UI
- 로그인/회원가입은 짧고 신뢰감 있는 입력 경험을 제공한다.
- 토스트, 모달, 자동완성, 채팅, 드롭다운은 같은 포커스·레이어·모서리·그림자 규칙을 공유한다.
- 모달은 키보드 포커스, 닫기, 스크롤, 모바일 높이를 확인한다.

## 4. 레이아웃과 반응형

- Desktop / Tablet / Mobile을 별도 디자인 상태로 검토한다. 데스크톱을 단순 축소하지 않는다.
- 320px부터 가로 overflow가 없어야 한다.
- 작은 화면에서는 정보 우선순위를 재배치하고, 숨김은 정보의 중요도에 따라 결정한다.
- Bento Grid는 CSS Grid의 minmax/min-width:0를 활용해 콘텐츠가 셀을 밀어내지 않게 한다.
- 포스터는 일관된 aspect-ratio와 object-fit을 유지한다.
- 헤더/내비게이션은 좁은 화면에서 터치 가능한 메뉴로 전환한다.
- 고정/스티키 UI는 실제 콘텐츠를 가리지 않도록 safe area와 하단 여백을 고려한다.

## 5. 접근성·상태 디자인

모든 인터랙티브 요소에 대해 다음을 검토한다.
- 키보드만으로 접근 가능하고 focus-visible이 명확한가?
- 텍스트와 UI 경계의 대비가 충분한가?
- 버튼/링크/입력의 역할과 accessible name이 분명한가?
- hover에만 의존하지 않는가?
- disabled/loading/error/success/empty 상태가 존재하는가?
- prefers-reduced-motion을 존중하는가?
- 이미지 대체 텍스트와 장식 이미지 처리가 올바른가?
- 터치 타깃은 가능하면 44×44px 이상인가?

## 6. 코드베이스 작업 규칙

- 작업 전 App.js, 페이지 컴포넌트, 관련 styled-components, 전역 스타일 조립 순서를 확인한다.
- 실제 사용되는 CSS/스타일 파일을 전수 조사한다. 파일명만 보고 미사용이라고 판단하지 않는다.
- 기존 className, styled-component export, props, 라우팅, API, 상태, 이벤트 핸들러를 임의로 바꾸지 않는다.
- 스타일 개선이 JSX 구조 변경을 요구하면 최소 변경만 하고 기능 테스트를 추가한다.
- 신규 토큰은 global/GlobalTokens.styles.js에 정의한다.
- 페이지별 스타일은 해당 페이지의 기존 스타일 모듈에 둔다. 전역 파일에 페이지별 셀렉터를 무한히 추가하지 않는다.
- !important, :has()의 광범위 사용, * 기반 시각 강제, 태그 선택자 기반 레이아웃 변경을 피한다.
- 중복 CSS와 충돌하는 선언을 찾아 근본 원인을 제거한다.
- 스타일 파일을 통째로 교체하기 전 현재 선택자와 DOM 사용처를 확인한다.
- 외부 이미지 URL이나 아이콘 라이브러리를 임의로 추가하지 않는다. 기존 에셋과 의존성을 우선한다.
- 코드 리뷰는 파일 간 영향 관계를 추적한다. 한 토큰 변경이 어느 화면에 영향을 주는지 확인한다.

## 7. 디자인 프로세스 (반드시 순서 준수)

### Phase A — Understand Anything 방식의 코드베이스 이해
1. 페이지/라우트 목록과 사용자 여정을 작성한다.
2. 각 페이지가 사용하는 컴포넌트와 스타일 파일의 의존 그래프를 만든다.
3. 전역 스타일 주입 순서와 중복/덮어쓰기/특이 선택자를 찾는다.
4. API 데이터가 실제로 렌더링되는 위치와 로딩·오류·빈 상태를 확인한다.
5. 변경 전 기준 화면과 기능 동작을 기록한다.

### Phase B — Superpowers식 사전 설계
1. 문제를 증상과 근본 원인으로 나눈다.
2. 페이지별 개선 목표와 비목표를 명시한다.
3. 변경 파일, 위험 요소, 회귀 테스트를 먼저 계획한다.
4. 가능한 작은 단위로 구현한다.
5. 테스트 실패 시 임시 우회보다 원인을 수정한다.

### Phase C — Art Direction
1. 한 문장으로 이번 릴리스의 시각적 콘셉트를 정의한다.
2. 컬러, 타이포, 그리드, 이미지 크롭, 밀도, 모션을 결정한다.
3. 홈 화면 하나만 예쁘게 만드는 것이 아니라 공통 요소와 페이지별 변주를 정의한다.
4. 실제 콘텐츠 길이/한국어/포스터 유무를 가정해 레이아웃을 설계한다.
5. 디자인 결정은 브랜드·사용자 목적·접근성 중 하나 이상의 이유를 가져야 한다.

### Phase D — Anti-slop / Impeccable 품질 게이트
다음 질문에 모두 답할 수 있어야 한다.
- 이 디자인이 MOMO가 아닌 다른 영화/리뷰 서비스에도 그대로 붙을 수 있는 범용 템플릿인가? 그렇다면 브랜드 고유 디테일을 다시 설계한다.
- 모든 섹션이 동일한 카드인가? 그렇다면 평면·분리선·여백·이미지 중심 레이아웃을 섞는다.
- 장식 요소가 기능/위계를 돕는가? 아니라면 제거한다.
- 글자 크기와 간격이 임의로 선택되었는가? 토큰과 위계에 맞춘다.
- 첫 화면에 시선이 어디로 가는지 명확한가?
- 한 화면에 너무 많은 강조색이나 그림자가 있는가?
- 빈 상태/오류 상태도 완성된 디자인인가?

### Phase E — 구현과 검증
1. 토큰 → 공통 요소 → 페이지별 구조 → 세부 상태 순으로 구현한다.
2. 각 페이지를 데스크톱/태블릿/모바일에서 확인한다.
3. 실제 브라우저에서 hover/focus/click/typing/scroll/navigation을 확인한다.
4. 기능 테스트와 빌드를 실행한다.
5. 시각 검토 결과를 페이지별로 기록하고 미완료 항목을 숨기지 않는다.

## 8. 검증 체크리스트

- [ ] 모든 라우트가 동일한 브랜드 언어를 공유한다.
- [ ] 각 페이지에 목적에 맞는 독자적 레이아웃이 있다.
- [ ] 홈 첫 화면의 시선 흐름이 명확하다.
- [ ] 카드·패널·버튼·폼의 밀도와 간격이 일관된다.
- [ ] 포스터 비율, 크롭, 텍스트 오버레이가 자연스럽다.
- [ ] 장식이 콘텐츠를 압도하지 않는다.
- [ ] 320 / 375 / 768 / 1024 / 1440px 폭에서 확인했다.

### Functional
- [ ] 모든 CTA가 올바른 동작을 한다.
- [ ] 링크·라우팅·검색·필터·정렬이 유지된다.
- [ ] 로그인/로그아웃/리뷰/관심영화 동작이 유지된다.
- [ ] 로딩/오류/빈 상태가 깨지지 않는다.
- [ ] 콘솔 오류와 네트워크 오류를 확인했다.

### Engineering
- [ ] 빌드와 관련 테스트가 통과한다.
- [ ] 신규 의존성을 불필요하게 추가하지 않았다.
- [ ] 기존 API 계약과 데이터 모델을 변경하지 않았다.
- [ ] 광범위한 !important나 임시 override를 추가하지 않았다.
- [ ] CSS 중복과 불필요한 규칙을 확인했다.
- [ ] 스크린샷/브라우저 증거 없이 시각 QA 완료라고 주장하지 않는다.

## 9. 리뷰 산출물

작업 보고에는 다음을 포함한다.
1. 발견한 근본 문제
2. 확정한 아트 디렉션과 토큰
3. 페이지별 변경 사항
4. 수정 파일과 영향 범위
5. 데스크톱/태블릿/모바일 시각 검증 결과
6. 기능/빌드/테스트 결과
7. 미검증 항목과 남은 위험

**정직성 규칙:** 실행하지 않은 테스트를 통과했다고 말하지 않는다. 브라우저를 열지 않았다면 시각 검증 완료라고 하지 않는다. 미리보기 URL이 없다면 없다고 명시한다.
